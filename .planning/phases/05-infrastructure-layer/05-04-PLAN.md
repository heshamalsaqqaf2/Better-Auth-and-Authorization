    ```typescript
    export interface RetryOptions {
      baseDelayMs?: number;    // default: 1000
      maxDelayMs?: number;     // default: 30000
      jitterFactor?: number;   // default: 100 (ms of random jitter added)
      systemComponent?: InfrastructureComponent;  // for InfrastructureError when retries exhausted
      errorCode?: string;      // for InfrastructureError when retries exhausted (default: "RETRY_EXHAUSTED")
    }
    ```
    
    Implementation (D-18):
    1. Async function with internal recursive helper `attempt(attemptCount: number): Promise<InfrastructureResult<T>>`
    2. Call `await fn()` — if result is Success, return it immediately.
    3. If result is Failure:
       - If `attemptCount >= maxRetries`, return `err(new InfrastructureError({ code: options.errorCode ?? "RETRY_EXHAUSTED", message: "All retry attempts exhausted", systemComponent: options.systemComponent ?? "Network", retryCount: attemptCount, retryStrategy: "exponential", cause: result.error }))`
       - Otherwise, compute delay with exponential backoff + jitter (D-18): `baseDelay * 2^attempt + random(0, jitterMax)`, clamped to `maxDelayMs`
       - Wait via `new Promise(resolve => setTimeout(resolve, delay))`
       - Return `attempt(attemptCount + 1)`
    4. Start with `attempt(0)`.
    
    Use closures, not class instances — all state is local to the recursion.

    Per D-17:
    ```typescript
    export function withTimeout<T>(
      fn: () => Promise<T>,
      ms: number,
      options?: { systemComponent?: InfrastructureComponent; errorCode?: string },
    ): Promise<InfrastructureResult<T>>
    ```
    
    Import:
    - `{ InfrastructureError } from "../Errors/infrastructure-error"`
    - `{ ok, err } from "@/Core/Foundations/Base/Abstracts/result-base"`
    - `type { InfrastructureResult } from "../Results/infrastructure-result"`
    - `type { InfrastructureComponent } from "../Contracts/infrastructure-component.type"`
    
    Implementation:
    1. Create a timeout promise: `new Promise<never>((_, reject) => setTimeout(() => reject(new Error("Timeout")), ms))` — but we catch it and return `err(InfrastructureError)` instead of rejecting.
    2. Use `Promise.race([fn(), timeoutPromise])`.
    3. If fn() resolves first: return `ok(result)`.
    4. If timeout fires first: return `err(new InfrastructureError({ code: options?.errorCode ?? "TIMEOUT", message: "Operation timed out", systemComponent: options?.systemComponent ?? "Network", retryStrategy: "exponential" }))`.
    
    Note: The timeout Promise rejection is caught internally and converted to an InfrastructureResult Failure. The wrapper never throws — always returns `Promise<InfrastructureResult<T>>`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Resilience wrappers→External fn | The wrappers execute user-provided functions (`fn`) that may make network calls, DB queries, etc. The wrappers themselves are pure runtime utilities with no network access. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-07 | Denial of Service | withTimeout | mitigate | Prevents indefinite blocking by rejecting after `ms` milliseconds. The timeout mechanism uses `setTimeout` + `Promise.race` — always resolves/rejects within bounded time. |
| T-05-08 | Information Disclosure | withRetry InfrastructureError | mitigate | When retries exhaust, the `cause` carries the last attempt's InfrastructureError which may contain unsanitized error details. This is acceptable because InfrastructureResult stays within the Infrastructure layer — sanitization happens at the Infrastructure→Application mapper boundary (Plan 03), not at the wrapper level. |
| T-05-09 | Denial of Service | withRetry delay calculation | mitigate | `baseDelay * 2^attempt` exponential growth is bounded by `maxDelayMs` clamp. Max delay per attempt is 30s. With default maxRetries=3, worst-case total wait is ~70s (1 + 2 + 4 seconds) which is safe for server environments. |
| T-05-SC | Tampering | npm/pip/cargo installs | accept | Zero external dependencies — native `Promise`/`setTimeout` only |
</threat_model>
