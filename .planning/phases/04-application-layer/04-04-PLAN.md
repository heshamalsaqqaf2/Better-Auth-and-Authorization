Create CQRS handler interfaces, decorator base classes, and the complete barrel chain.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CQRS handler interface → concrete implementation | Contract enforced at compile time; runtime depends on concrete class |
| Decorator → inner handler | Decorator wraps execution — could intercept/modify results or errors |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-10 | Elevation of Privilege | ICommandHandler/IQueryHandler | accept | These are contracts, not enforcement points. Authorization responsibility belongs to a concrete decorator (LoggingUseCaseDecorator etc.) that will check permissions at execution time in module phases |
| T-04-11 | Tampering | Decorator base classes | mitigate | Abstract execute() is declared abstract — concrete decorators must implement it. No default pass-through behavior that could accidentally bypass inner handler logic. Decorators are applied explicitly by composition |
| T-04-12 | Information Disclosure | All barrels | accept | Barrel files re-export existing types/functions — no new code or data transformation. Information disclosure risk is carried by the exported modules themselves, not the barrels |
</threat_model>
