### Task 2: Create presentation-error.types.ts (shapes + union)

<read_first>
- src/Core/Kernel/Primitives/Types/correlation-id.type.ts (branded type reference)
- src/Core/Foundations/Application/Errors/Specific/command-validation.error.ts (fieldErrors type reference)
</read_first>

<action>
Create `src/Core/Foundations/Presentation/Errors/presentation-error.types.ts` containing **types only** (following the separation pattern where Contracts hold the types and `{layer}-error.ts` holds the runtime):

1. **5 variant shape types** (`ValidationErrorShape`, `NotFoundErrorShape`, `AuthorizationErrorShape`, `SystemErrorShape`, `NetworkErrorShape`) — each with `_tag` discriminant, `errorCode: string`, plus variant-specific fields:

   - **ValidationErrorShape**: `_tag: 'ValidationError'`, `errorCode: string`, `fieldErrors: Record<string, string[]>`, no `userMessage` (fieldErrors conveys it)
   - **NotFoundErrorShape**: `_tag: 'NotFoundError'`, `errorCode: string`, `userMessage: string`, `suggestedAction?: string`
   - **AuthorizationErrorShape**: `_tag: 'AuthorizationError'`, `errorCode: string`, `userMessage: string` (no requiredPermission per D-04)
   - **SystemErrorShape**: `_tag: 'SystemError'`, `errorCode: string`, `userMessage: string`, `severity: 'warning' | 'error' | 'critical'`
   - **NetworkErrorShape**: `_tag: 'NetworkError'`, `errorCode: string`, `userMessage: string`, `retryable: boolean`

2. **`PresentationError` discriminated union type** = `ValidationErrorShape | NotFoundErrorShape | AuthorizationErrorShape | SystemErrorShape | NetworkErrorShape`

All shapes are plain object types — no classes, no `instanceof`.
</action>

<acceptance_criteria>

- `presentation-error.types.ts` exports `PresentationError` union type
