<objective>
Create the three Server Actions (sign-in, sign-up, sign-out) with the Better Auth API route handler, all returning uniform PresentationResult<T | null>.

Purpose: Server Actions are the Presentation entry point for auth operations. They resolve UseCases from the Composition Root, call them, map ApplicationResult to PresentationResult, and return serialization-safe responses. This is the boundary where OOP meets DUs.
</objective>

**PresentationResult mapping (from Phase 6):**
- `mapAppResultToPresentation<T>(result: ApplicationResult<T>): PresentationResult<T>` — converts Success → successResult(), Failure → failureResult() with error mapped via mapAppErrorToPresentation
- `mapAppErrorToPresentation(error: ApplicationError): PresentationError` — maps ApplicationError variants to PresentationError variants

**Action types:**
- `SignInFormState = PresentationResult<AuthResponseDTO | null>` — for useActionState
- `SignUpFormState = PresentationResult<AuthResponseDTO | null>`

**Better Auth API route:**
- `src/app/api/auth/[...all]/route.ts` — Next.js catch-all route that exports GET/POST handlers
- Imports the Better Auth server handler
- Delegates all auth API requests to Better Auth

**Error handling in actions:**
- Server Action try/catch wrapper: "use server" cannot throw across boundary intentionally
- Unexpected errors → failureResult(systemError("An unexpected error occurred"))
- Validation errors (bad form data) → failureResult(validationError([...fieldErrors]))

| Threat ID | Category | Component | Disposition | Mitigation |

| T-08-12 | Spoofing | sign-in.action | mitigate | Delegates authentication to Better Auth — no custom credential validation |

| T-08-14 | CSRF | Server Actions | accept | Next.js Server Actions are inherently CSRF-protected (same-origin, form action binding) |
