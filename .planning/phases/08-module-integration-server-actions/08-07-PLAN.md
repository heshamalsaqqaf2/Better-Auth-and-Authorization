<objective>
Create the three Server Actions (sign-in, sign-up, sign-out) resolving UseCases from the InversifyJS container, with the Better Auth API route handler, all returning uniform PresentationResult<T | null>.

Purpose: Server Actions are the Presentation entry point for auth operations. They resolve UseCases from the InversifyJS container via `getContainer().get<T>(AUTH_TOKENS.XXX)`, call them, map ApplicationResult to PresentationResult, and return serialization-safe responses. This is the boundary where OOP (UseCases) meets DUs (PresentationResult).
</objective>

```typescript
  // 2. Resolve SignInUseCase from InversifyJS container
  // 3. Call useCase.execute(dto)
  // 4. Map ApplicationResult → PresentationResult
  // 5. Return PresentationResult
}
```

**Container resolution pattern:**
```typescript
import { container } from "@/CompositionRoot/container";
// Direct import of the container singleton — NOT getContainer()
// The container has already loaded all ContainerModules via CompositionRoot/index.ts

const useCase = container.get<SignInUseCase>(AUTH_TOKENS.SIGN_IN_USE_CASE);
const result = await useCase.execute(dto);
return mapAppResultToPresentation(result);
```

**Important:** The `container` from `@/CompositionRoot/container` is already populated because `CompositionRoot/index.ts` runs on import. Server Actions import from the barrel which triggers module loading.

      ```typescript
        prevState: PresentationResult<AuthResponseDTO | null>,

          const dto: SignInDTO = { email, password };
          const result = await useCase.execute(dto);

          return mapAppResultToPresentation(result);
        } catch (error) {
          return failureResult(systemError("An unexpected error occurred. Please try again."));
        }
      }
      ```

      ```typescript
        prevState: PresentationResult<AuthResponseDTO | null>,
        formData: FormData,
      ): Promise<PresentationResult<AuthResponseDTO | null>> {
        try {
          const name = formData.get("name") as string | null;
          const email = formData.get("email") as string | null;
          const password = formData.get("password") as string | null;

          // Validation
          const fieldErrors: Array<{ field: string; message: string }> = [];
          if (!name) fieldErrors.push({ field: "name", message: "Name is required" });
          if (!email) fieldErrors.push({ field: "email", message: "Email is required" });
          if (!password) fieldErrors.push({ field: "password", message: "Password is required" });
          else if (password.length < 8) fieldErrors.push({ field: "password", message: "Password must be at least 8 characters" });
          if (fieldErrors.length > 0) return failureResult(validationError(fieldErrors));

          const useCase = container.get<SignUpUseCase>(AUTH_TOKENS.SIGN_UP_USE_CASE);
          const dto: SignUpDTO = { name, email, password };
          const result = await useCase.execute(dto);

          return mapAppResultToPresentation(result);
        } catch (error) {
          return failureResult(systemError("An unexpected error occurred. Please try again."));
        }
      }
      ```

| Server Action → Client | Only PresentationResult crosses the serialization boundary |

| Threat ID | Category | Component | Disposition | Mitigation |
|-----------|----------|-----------|-------------|------------|
| T-08-07-01 | Spoofing | sign-in.action | mitigate | Delegates authentication to Better Auth — no custom credential validation |
| T-08-07-02 | Info Disclosure | sign-in.action | mitigate | Generic error messages for all failures — no "user exists" disclosure |
| T-08-07-03 | CSRF | Server Actions | accept | Next.js Server Actions are inherently CSRF-protected (same-origin, form action binding) |
</threat_model>
