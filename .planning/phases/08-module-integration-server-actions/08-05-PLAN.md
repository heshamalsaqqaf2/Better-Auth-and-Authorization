<objective>
Create the Authentication module's Application layer — UseCases implementing Foundation ICommandHandler/IQueryHandler contracts with InversifyJS decorator-based injection, DTOs, and mappers.

Purpose: Application layer orchestrates business operations. UseCases implement ICommandHandler<TCommand, TResult> or IQueryHandler<TQuery, TResult> from Foundation contracts, accepting (dto, ctx: RequestContext) per CQRS pattern. UseCases use constructor injection via @injectable() + @inject() with Symbol.for() tokens from AUTH_TOKENS. Error mappers receive { operationName, correlationId } from ctx for proper error chain propagation. Each UseCase is registered in the ContainerModule and resolved by Server Actions (08-07). No direct access to Better Auth or Drizzle from this layer.
</objective>

**UseCase pattern — ICommandHandler with RequestContext:**
```typescript
import { injectable, inject } from "inversify";
import type { ICommandHandler } from "@/Core/Foundations/Application/Contracts/command-handler.contract";
import type { RequestContext } from "@/Core/Foundations/Application/Contracts/request-context.contract";
import { AUTH_TOKENS } from "@/Modules/Authentication/Composition/tokens";

@injectable()
export class SignInUseCase implements ICommandHandler<SignInDTO, AuthResponseDTO> {
  constructor(
    @inject(AUTH_TOKENS.BETTER_AUTH_SERVICE) private readonly authService: BetterAuthService,
  ) {}

  async execute(dto: SignInDTO, ctx: RequestContext): Promise<ApplicationResult<AuthResponseDTO>> {
    try {
      const result = await this.authService.signIn(dto.email, dto.password);
      if (result.isFailure()) {
        return err(mapInfrastructureToAppError(result.error, {
          operationName: "SignIn",
          correlationId: ctx.correlationId,
        }));
      }
      const data = result.data;
      return ok({
        user: { id: data.user.id, name: data.user.name, email: data.user.email },
        session: { id: data.session.id, expiresAt: data.session.expiresAt.toISOString() },
      });
    } catch (error) {
      return err(new UseCaseExecutionError({
        cause: error instanceof Error ? error : new Error(String(error)),
        operationName: "SignIn",
        correlationId: ctx.correlationId,
      }));
    }
  }
}
```

**Why explicit @inject() is required:**
- Next.js 16 uses SWC for transpilation
- SWC supports `experimentalDecorators` (legacy decorator transform) but NOT `emitDecoratorMetadata`
- Without metadata emission, InversifyJS cannot auto-resolve constructor parameter types
- Each constructor parameter MUST have an explicit `@inject(TOKEN)` decorator

**Why Phase 8 UseCases inject only BetterAuthService (no repositories):**
- Better Auth handles all 4 core auth operations (signIn, signUp, signOut, getSession) internally via its Drizzle adapter
- For Phase 8 (email/password only), Better Auth provides everything needed: user creation, credential validation, session management
- AuthQueryRepository exists (created in 08-04) but is NOT injected into Phase 8 UseCases — it is scaffolded for Phase 9 when custom queries are needed
- This keeps UseCases lean and avoids redundant DB lookups (Better Auth already validates internally)

**DTO shapes:**
```typescript
interface SignInDTO { email: string; password: string; }
interface SignUpDTO { name: string; email: string; password: string; }
interface AuthResponseDTO { user: UserDTO; session: SessionDTO; }

interface SessionDTO { id: string; expiresAt: string; }  // ISO string, not Date
interface SignOutDTO { headers: Headers; }  // Headers needed for Better Auth API
interface SessionCheckDTO { headers: Headers; }
```
