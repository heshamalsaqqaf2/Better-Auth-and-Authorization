**Domain error pattern (from CONTEXT.md D-14):**
- Each domain error extends DomainError from Foundations
- Sets `businessRule` to a descriptive string naming the violated rule
- Sets `aggregateId` if applicable (empty string for auth errors without an aggregate)
- Uses hardcoded uppercase-snake error code (e.g., `USER_NOT_FOUND`, `INVALID_CREDENTIALS`)
- Layer is already set to DOMAIN by DomainError base class

**Repository Command interface contract (D-14):**
```typescript
interface ICommandAuthRepository {
  createUser(data: CreateUserInput): DomainResult<UserAggregate>;
  // Future: updateUser, deleteUser
}
```

**Repository Query interface contract:**
```typescript
interface IQueryAuthRepository {
  findUserByEmail(email: string): DomainResult<UserAggregate | null>;
  findUserById(id: string): DomainResult<UserAggregate | null>;
  // Future: findSessionByToken
}
```

**Aggregate/Entity models:**
- UserAggregate: { id: string; name: string; email: string; emailVerified: boolean; createdAt: Date; updatedAt: Date }
- SessionData: { id: string; userId: string; expiresAt: Date; createdAt: Date }
</interfaces>
