<objective>
Migrate from the custom lightweight Container class to InversifyJS with professional Composition Root patterns. Install inversify + reflect-metadata, enable decorator support in tsconfig, replace container.ts with a factory function, introduce a bootstrap layer with lazy-initialized singleton, add startup validation, provide a test container factory, convert registration.ts to a ContainerModule, and add @injectable() to BetterAuthService.

Purpose: Establish InversifyJS as the project's DI container (D-02) following production-grade Composition Root best practices. The container is NEVER exported directly (prevents Service Locator anti-pattern) — access is exclusively through a resolve<T>() helper. Startup validation catches missing/circular bindings early. A test container factory enables isolated test containers with mock overrides. All subsequent plans (08-04 through 08-09) build on top of this setup.
</objective>

**@injectable() + @inject() decorator usage (SWC requirement):**

- Use `@injectable()` on every class resolved via DI
- Use explicit `@inject(Symbol.for(...))` on ALL constructor parameters — this is MANDATORY
- ⚠️ CRITICAL: SWC (Next.js compiler) supports `experimentalDecorators` but does NOT support `emitDecoratorMetadata`. Without `@inject()` on every parameter, InversifyJS cannot resolve constructor dependencies and will throw at runtime.
- Pattern: `constructor(@inject(AUTH_TOKENS.XXX) private readonly dep: SomeType) {}`
- Import `{ injectable, inject }` from "inversify"

**BetterAuthService binding rules (D-17):**
- Infra services: singleton scope (`.inSingletonScope()`)
- UseCases/Application services: transient (default — no scope decorator)
