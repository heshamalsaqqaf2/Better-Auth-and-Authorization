    Per D-11: `ResultBase<T, E extends ErrorBase>` is abstract with only four abstract members: `abstract readonly isSuccess: boolean`, `abstract readonly isFailure: boolean`, `abstract readonly data?: T`, `abstract readonly error?: E`. The monadic methods (`map`, `flatMap`, `mapError`, `match`, `fold`, `tap`, `tapError`) are NOT abstract on the base — they are implemented concretely on Success and Failure subclasses.

    Import the contract types: `import type { ResultBase as ResultBaseContract }` and `import type { ErrorBase }` from the Kernel contract paths.

    Optionally declare that the class structurally satisfies the contract interface. The `implements` clause on Success/Failure is not strictly required but types should be compatible.

    `Success<T>` extends `ResultBase<T, never>`:
    - `isSuccess = true`, `isFailure = false`
    - `data: T` via constructor parameter
    - `error = undefined`
    - `map<U>(fn: (data: T) => U): Success<U>` — applies fn and returns new Success
    - `flatMap<U>(fn: (data: T) => ResultBase<U, never>): ResultBase<U, never>` — applies fn
    - Per D-19: `mapError()` returns `this` without calling fn
    - `match<R>(handlers)` and `fold<R>(onSuccess, onFailure)` call onSuccess/onSuccess with data
    - `tap(fn)` calls fn with data, returns `this`
    - Per D-18: `tapError()` returns `this` without calling fn

    `Failure<T, E extends ErrorBase>` extends `ResultBase<T, E>`:
    - `isSuccess = false`, `isFailure = true`
    - `data = undefined`
    - `error: E` via constructor parameter
    - Per D-16: `map()` returns `this` (typed as `ResultBase<U, E>`) without calling fn
    - Per D-17: `flatMap()` returns `this` without calling fn
    - `mapError<F extends ErrorBase>(fn: (error: E) => F): Failure<T, F>` — applies fn to error
    - `match<R>(handlers)` and `fold<R>(onSuccess, onFailure)` call onFailure/onFailure with error
    - Per D-18: `tap()` returns `this` without calling fn
    - `tapError(fn)` calls fn with error, returns `this`

    Per D-14: `ok()` and `err()` are standalone exported functions (not static methods):
    - `export function ok<T>(data: T): Success<T>` — wraps data in Success
    - `export function err<E extends ErrorBase>(error: E): Failure<never, E>` — wraps error in Failure

    The return type of `Failure.map()` should be `ResultBase<U, E>` (not `Failure<U, E>`) to satisfy the contract signature. Use an explicit type annotation for the return value.
