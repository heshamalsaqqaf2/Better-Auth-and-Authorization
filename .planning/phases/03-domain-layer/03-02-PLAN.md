  <action>
    Per D-13: Create `isDomainError()` duck-typing type guard.

    ```
    import { DomainError } from "./domain-error";

    export function isDomainError(value: unknown): value is DomainError {
      if (value === null || value === undefined) return false;
      if (typeof value !== "object") return false;

      const obj = value as Record<string, unknown>;

      if (typeof obj.businessRule !== "string") return false;
      if (typeof obj.aggregateId !== "string") return false;

      return true;
    }
    ```

    Per D-13: The guard checks for `businessRule` (string) and `aggregateId` (string) properties on the error object — this is the duck-typing signature that distinguishes domain errors from errors of other layers.

    Per D-14: No `isDomainResult()` type guard is created — DomainResult is a type alias, and runtime discrimination is done via `isDomainError()` on the error property of a result.

    The guard follows the same pattern as `isBaseError` from Base/TypeGuards:
    - Null/undefined check
    - Non-object check
    - Property-type structural checks
    - No `instanceof` usage
  </action>
